The HTTP composition probe confirmed an existing provider isolation defect using synthetic data in an isolated child process.
Writing a special tenant name mutated Object.prototype and let another tenant read the synthetic TMK.
The configured legacy secrets-path regression also confirmed that existing local keys must remain intact during HTTP composition.
This small security prerequisite belongs to the approved implementation scope; CV-16 waits for its closure.

Use dictionaries without inherited properties on initial, missing-file, loaded, and new-tenant paths.
Treat reserved-looking tenant and secret names as ordinary data, preserving valid existing records and public APIs.
Do not drop existing fields, replace keys, log secrets, redesign persistence, or alter unrelated configuration.
Keep synthetic regression pollution inside an isolated process or restore prototypes reliably after every assertion.

Write the failing isolation regression first. Verify special names, missing/inherited keys, reload, deletion, TMK isolation, and valid existing JSON preservation.
Proving commands: `npm test -- tests/security/tenant-secrets-isolation.test.ts tests/unit/secrets.service.test.ts tests/unit/tenant.service.test.ts; npm run build`.
Fresh review and independent integrated checking remain required. Only the lead changes state or commits.
